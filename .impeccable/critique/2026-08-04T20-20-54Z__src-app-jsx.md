### Design Specificity Verdict

**LLM assessment**: This is not a generic form-app skin. The live trial-scoring widget — four large color-coded chips, an inline undo, a running clock and trial count, a swipe between "Prioritaires" and "Par personne" — is built around a specific physical scene: a standing educator glancing at a tablet between two learners. French ABA vocabulary, initials-only identity, and "configuration mémorisée" for recurring ateliers show real domain modeling, not a translated template. The fixed cold categorical palette carrying clinical meaning (guidance level, crisis function) across both themes is a genuine "this app, this data" decision.

Where it slips back toward generic: the crisis/ABC logging form is a long, undifferentiated vertical form indistinguishable from any incident-report web app — no pacing, no acknowledgment that the user is mid-crisis beyond a red header, and it doesn't use the one piece of context the app already holds (which learner is on-screen) to save a step. That's a specificity failure at exactly the highest-stakes moment in the product.

**Deterministic scan**: `detect.mjs --json src/App.jsx` returned exit code 2, **15 findings**, all rule `design-system-color` (color literals outside DESIGN.md's token set), all advisory severity. 14 of 15 are `rgba(0,0,0,0.5)`/`rgba(0,0,0,0.45)` modal backdrop scrims (App.jsx:623, 664, 2825, 3203, 4840, 4927, 5017, 6147, 8024, 8102, 8173, 8188, 8245, 9171) — low-risk, standard overlay-dimming pattern, but technically un-tokenized. The 15th, at **line 4772**, is `rgba(32,41,31,0.35)` — an olive-tinted black backdrop on the side drawer, inconsistent with the rest of the app's blue-indigo system. The LLM review independently flagged this exact same line as "likely accidental, worth a token cleanup" without having seen the detector output — a genuine convergent finding, not overlap by coincidence.

**Visual overlays**: No native browser-canvas tool is exposed in this harness, so no live `[Human]` tab could be shown in your browser. Instead, Assessment B ran the detector overlay against the isolated agent's own headless browser and captured full-page screenshots at each step; those are attached separately. On the Session screen's "Par personne" tab — the single most-repeated view in the app — the overlay's console output flagged **10 anti-patterns**: 5× `low-contrast` (white text on `#00A870` teal 3.1:1, `#FF8A3D` amber 2.3:1 ×2, `#FF4D6D` coral 3.2:1 ×2 — all below the 4.5:1 AA floor) and 4× `undersized-ui-text` (10px labels on "Indépendant," "Guidance partielle," "Guidance totale," "Mauvaise réponse"). Both were cross-checked against source (`CAT_TEAL`/`CAT_AMBER`/`CAT_CORAL` constants and the four category labels) and confirmed real, not false positives. Export screen added 5 more: a repeat low-contrast amber instance, `all-caps-body` (66 chars of uppercase body text), `line-length` (~138 chars/line), `overused-font` (Space Grotesk at 55% of text share), and `nested-cards`. Suivi showed one `nested-cards` finding in both light and dark. One methodology artifact surfaced and was correctly discarded: calling the detector's raw API a second time after overlays had already painted inflated the counts because it rescanned its own overlay badges as page content — the console-logged numbers above are the clean ones.

### Overall Impression

The core loop — start a session, tap through trials — is genuinely well built: fast, legible, low-friction, and it respects the product's central constraint (speed while standing, mid-intervention). That loop is where most of the design attention clearly went, and it shows. The product falls apart at its two edges: the crisis-logging form, which is the highest-stakes screen in the app and the least designed one, and the color system's execution, where a currently-illegible pair of guidance-button states sit inside the most-repeated tap target in the whole product. Both assessments converged independently on the same two weak points — that's a stronger signal than either alone.

### What's Working

1. **The trial-scoring widget** — four large, color-coded, mono-labeled buttons with an inline "annuler" and a running count. This is what Operate mode should look like: no decoration, maximal legibility, one-tap correction.
2. **"Configuration mémorisée"** — surfacing only what's *new* since the last saved atelier setup, instead of re-showing the full roster to reverify, is a real working-memory accommodation most tools this size skip.
3. **Theme-token discipline at the primitive level** — `Btn`/`Card`/`Chip`/`Field` correctly swap CSS-variable tokens rather than literals almost everywhere, and both light/dark screenshots hold contrast where that pattern is actually followed.

### Priority Issues

**[P0] Crisis form saves with zero validation.** The save action has no `disabled` guard of any kind — an educator can tap "Terminer et enregistrer" with no student, no A/B/C data, and no function selected, and it succeeds silently. This is the confirmed, live-reproduced root cause of the "Personne non renseignée" entry visible on Export.
**Why it matters**: This is a clinical record about a person with a disability. A record that can be blank and still "save successfully" undermines the one thing Export exists to produce — something a supervisor can trust.
**Fix**: Require a selected student before save is enabled (the app already knows this at the moment the form opens in nearly every real case — see next issue). If A/B/C is entirely empty, don't block save, but surface an explicit confirmation ("Fiche enregistrée sans détail de comportement — compléter maintenant ?") instead of silence.
**Suggested command**: `/impeccable harden`

**[P0] Crisis form doesn't pre-fill the learner already on screen.** The crisis-creation handler hardcodes an empty student field even when a session is active and a specific learner is currently displayed. During a single-learner session — the majority case — the app already knows who the crisis is about and asks anyway, at the worst possible moment to be asking.
**Why it matters**: Compounds the P0 above directly: this is the actual reason the field gets skipped under time pressure, not carelessness.
**Fix**: Thread the currently-displayed student id into the crisis/ABC open handlers; pre-select it and let the educator change it if wrong, rather than requiring them to set it from nothing.
**Suggested command**: `/impeccable harden`

**[P1] Guidance-button text fails contrast on the most-tapped surface in the app.** White text on amber (`#FF8A3D`, ≈2.3:1) and coral (`#FF4D6D`, ≈3.2:1) both fail WCAG AA 4.5:1; teal (≈3.1:1) is borderline. This is on the four category buttons tapped on every single trial, all session, every day.
**Why it matters**: In the bright, variable-lit rooms this product is actually used in, distinguishing "Guidance partielle" from "Guidance totale" by color+text gets harder exactly where scoring accuracy matters.
**Fix**: Darken amber/coral (or the reverse: switch those two swatches to dark text) — a one-time, low-risk change since the palette is already documented as fixed across themes.
**Suggested command**: `/impeccable audit` (contrast pass), then `/impeccable colorize`

**[P1] CRISE and ABC are icon-only, unlabeled, and their tooltip never fires on touch.** These are the two actions the product itself defines as "always reachable," yet a first-time or infrequent user (substitute educator, agency staff) has no on-screen text to learn what they open — only a `title` attribute, which is inert on a tablet.
**Why it matters**: One of these opens a clinical incident record. Undiscoverable-until-memorized is a real risk for exactly the users most likely to need it unprepared.
**Fix**: Add a persistent micro-label under/beside each icon, or a one-time coach-mark on first use.
**Suggested command**: `/impeccable clarify`

**[P2] Two real decision points exceed 4 visible options.** The objective-type selector (5 modes) and the crisis "Fonction supposée" selector (5 functions) both cross the working-memory threshold the app otherwise respects well elsewhere. The crisis one is the higher-stakes instance, since it's chosen during/right after a crisis.
**Why it matters**: Minor on its own, but it's the same pattern (undifferentiated long lists) that shows up at the crisis form generally — a hint the crisis flow got less design iteration than the session flow.
**Fix**: Group into a primary set + "Autre," or keep 5 as a deliberate, documented exception.
**Suggested command**: `/impeccable layout`

### Persona Red Flags

**Riley (stress tester, logging a crisis mid-intervention)**: Taps the unlabeled CRISE button (P1); lands on a long red form where "Personne concernée" is the third section down, easy to skip while still watching the learner; nothing stops Riley from tapping "Terminer et enregistrer" the moment the immediate danger passes, producing exactly the blank/half-filled record this app's own live-reproduced bug demonstrates. No confirmation of what was actually captured — the relief of "it's logged" is provided whether or not the data is usable.

**Jordan (first-timer, starting a session and logging a trial)**: The bottom bar shows three labeled tabs plus two icon-only circles (ABC, CRISE) with no text and no working tooltip on tablet — despite the brief itself framing these as the two buttons that must always be reachable. Separately, the drawer's menu presents 9 flat, unsectioned items with no visual grouping between everyday content items (Ateliers, Personnes) and security-sensitive ones (Mots de passe, Données) — Jordan has to read every label to orient.

**Sam (accessibility-dependent)**: The guidance-scoring buttons — tapped constantly, all session — fail WCAG AA contrast on 2 of 4 states and border on failing a third (P1, confirmed independently by both assessments). In a bright classroom or for anyone with mild low vision, telling "GP" from "GT" apart becomes harder exactly where scoring accuracy is the whole point. `Field` inputs also have no dedicated focus treatment, a gap DESIGN.md itself already acknowledges.

### Minor Observations

- The pause-state banner uses the accent color as a passive status background — a documented violation of "L'Accent Seul" (accent reserved for primary action + current selection only).
- Crisis red is reused on the generic "Abandonner la séance" destructive button, outside its documented crisis-only scope.
- ~15 call sites hardcode `'#fff'` for selected-chip text instead of the `accent-ink` token; harmless today because the categorical palette is theme-fixed by design, but it's a literal deviation from DESIGN.md's own "Contraste par Thème" rule and a drift risk if any categorical color is ever adjusted.
- The side-drawer backdrop uses an olive-tinted black (`rgba(32,41,31,0.35)`) instead of the neutral black used everywhere else — flagged independently by both the LLM review and the deterministic scan.
- Suivi and Export show nothing from a currently-active, unfinished session — worth confirming this is the intended model, since checking progress mid-session seems like a plausible need.
- The lock screen carries no app name or wordmark anywhere — a tablet handed off cold gives no orientation cue that it's even the right app.

### Questions to Consider

- If the crisis form's field order buries "Personne concernée" under "Mesures annexes," and save has no validation at all — was this form used end-to-end under real time pressure before shipping, or only reviewed calmly, filling every field in order?
- The categorical palette is documented as deliberately fixed across themes specifically for legibility — so why does the one place that matters most for legibility, the guidance buttons, use two colors from that exact palette that measurably fail contrast?
- Is the label-less CRISE/ABC bottom bar an intentional bet that muscle memory beats a text label for daily users? Has that actually been timed for a first-week hire under pressure, or is it untested?
